# Pusher 新推送服务开发文档

> 目标读者：想给 Pusher 加一个新内置推送服务的开发者。
> 当前代码是 Swift 重写版，老文档里的 ObjC 内容已全部过时。

---

## 1. 要做的事（总共四步）

1. 新建 `Sources/Core/Services/<名字>Service.swift`，实现 `PushService` 协议。
2. 新建 `Sources/Preferences/Resources/<名字>.plist` 设置界面。
3. 在 `ServiceRegistry.addableServices` 里加一行 `.init(<名字>Service.self)`。
4. `Sources/Preferences/Resources/zh-Hans.lproj/Localizable.strings` 加显示名（如有）。

不需要改 Makefile（Swift 源文件自动被扫描），也不需要 `+load` 注册。

---

## 2. 服务长什么样

以 Bark 为例，这是全部代码（`Sources/Core/Services/BarkService.swift`）：

```swift
import Foundation

public enum BarkService: PushService {
    public static let serviceName = "Bark"

    public static func url(eventName: String, dbName: String, serverURL: String) -> String {
        let base = serverURL.isEmpty ? "https://api.day.app" : serverURL
        return (base.hasSuffix("/") ? String(base.dropLast()) : base) + "/"
    }

    public static func request(context: BulletinContext, config: ServiceConfig) -> PushRequest? {
        var infoDict: [String: Any] = [
            "title": context.displayTitle,
            "body": context.displayMessage,
        ]
        // 可选参数：配置里有值才发送
        for (prefKey, apiName) in parameters {
            let value = config.raw.string(prefKey) ?? ""
            if !value.isEmpty { infoDict[apiName] = value }
        }

        let urlString = config.raw.string(PrefKey.url, default: "")
            + config.raw.string(PrefKey.key, default: "")
        return withLogBody(
            PushRequest(urlString: urlString, infoDict: infoDict),
            infoDict
        )
    }

    public static func defaultPrefs() -> [String: Any] {
        ["serverURL": "https://api.day.app", /* 各参数默认空 */]
    }

    public static func defaultCustomAppPrefs() -> [String: Any] { [:] }
}
```

写一个新服务就是在回答四个问题：

| 问题 | 对应实现 |
| --- | --- |
| 这个服务叫什么 | `serviceName` |
| 推到哪个 URL | `url(...)` 和 `request(...)` 里拼 URL |
| 请求体长什么样 | `request(context:config:)` |
| 新实例一开始填什么 | `defaultPrefs()` |

## 3. 收到通知时你拿到什么

`request(context:config:)` 的 `context` 是通知内容，**不接触任何 SpringBoard 私有类**：

| 字段 | 说明 |
| --- | --- |
| `title` / `subtitle` / `message` | 通知的原始字段 |
| `displayTitle` | `"应用名: 标题"` |
| `displayMessage` | 副标题 + 内容拼好的整句 |
| `appID` / `appName` | 来源应用的 bundle ID / 显示名 |
| `date` | 通知时间（永不为 nil） |
| `isTest` | 是否测试推送 |
| `attachmentURL` | 附件文件 URL，无则 nil |
| `iconImage` | 应用图标（懒加载，较贵，按需取） |

`config` 是这个实例的配置。`config.raw` 是一个字典，键就是设置页 plist 里的
`key`——用户在设置页填了什么，这里就有什么。

## 4. 返回的请求

```swift
PushRequest(urlString: "https://...", infoDict: [...])
```

默认 `POST` + JSON。其它选项：

```swift
var request = PushRequest(urlString: ..., infoDict: ...)
request.method = "GET"       // GET/HEAD 时 infoDict 自动拼进 URL query
request.bodyType = "form"    // 其它方法默认 json，可改 form
```

- **图片**：`infoDict` 里直接放 `UIImage`，发送前自动转 Base64。
- **日志**：用 `withLogBody(request, infoDict)` 包装，Base64 字段自动替换成
  `<image>`，避免日志里塞一大坨。Base64 字段名不叫 `icon`/`image` 的话，
  覆写 `logImageDataProperties` 返回自己的字段名列表。

## 5. 设置界面

`Sources/Preferences/Resources/<名字>.plist`，和实例存储是一一对应的：

```xml
<dict>
  <key>items</key>
  <array>
    <dict><key>cell</key><string>PSGroupCell</string><key>label</key><string>Credentials</string></dict>
    <dict>
      <key>cell</key><string>PSEditTextCell</string>
      <key>key</key><string>key</string>          <!-- config.raw["key"] -->
      <key>label</key><string>Key:</string>
    </dict>
    ...
  </array>
</dict>
```

规则：

- 每个**值格子**的 `key` 就是 `config.raw` 里的字段名。
- 必须有一行 `App List`（`NSPAppListController`）和 `App Customization`
  （`NSPCustomizeAppsController`）——这是应用过滤和逐应用覆盖的入口，框架会自动
  带上「设备条件」「通知设置条件」「日志」「测试推送」等公共尾巴。
- plist 的文件名必须等于 `serviceName`。

几个现成的模式可以抄：

| 想要什么 | 看哪个服务的 plist |
| --- | --- |
| 密钥输入框 + 自定义服务器 | `Bark.plist` |
| 下拉选择（认证方式等） | `Custom.plist` |
| 开关（包含图标等） | `Pushover.plist` |
| 每应用覆盖字段 | `Wechat.plist` |

## 6. 异步：先拿 token 再推送（如企业微信）

覆写异步版本即可，同步版不用写：

```swift
public static func request(
    context: BulletinContext, config: ServiceConfig,
    completion: @escaping (PushRequest?) -> Void
) {
    fetchToken(config: config) { token in
        guard let token else { completion(nil); return }   // nil = 放弃本次推送
        completion(buildRequest(context: context, config: config, token: token))
    }
}
```

token 缓存参考 `WechatService` 的做法：按 `corpid|corpsecret` 缓存，留 60 秒
安全余量，过期失效，并发去重（single-flight）。

如果要根据**响应**重发（比如 token 失效 errcode 40014），用 `resendHandler`：
发送器收到响应后回调你，你刷新请求后回调 `completion(newRequest, false)`，
框架自动重发。重发与网络重试共享同一份预算，不会无限循环。

## 7. 图标和图片

协议里两个声明：

```swift
public static var supportsIcon: Bool { true }    // payload 带 icon 字段
public static var supportsImage: Bool { true }   // payload 带 image 字段
```

- 声明了能力，实例设置页才会显示「包含图标」「包含图片」开关。
- Bark 两个都是 `false`：它的 body 是自己拼的 `title`/`body`，共享字段放不进去，
  而且它的 `image` 参数是图片 **URL** 不是 Base64。
- 用户开了开关之后，`baseInfoDict(...)` 会把图标/图片放进共享 data dict
  （IFTTT、Pusher Receiver、自定义 webhook 用这套）。自己拼 body 的服务
  想用图标就自己取 `context.iconImage`。

## 9. 附：JS 自定义服务

不想写 Swift 的话，用户可以在应用里自己写 JS 服务（服务 → + → 写脚本），
脚本拿到同样的 `bullet` 对象和 `push()` 函数。只有想**内置**一个服务、
让所有用户开箱即用时才需要动 Swift。给 AI 生成脚本用的提示词在
应用内「指南 → 复制 AI 提示」。
