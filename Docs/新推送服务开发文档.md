# Pusher 新推送服务开发文档

> 本文基于当前仓库代码编写，以 `NSPushRequest` 重构后的实现为准。
> 目标读者：想给 Pusher 新增一个内置推送服务的开发者。

---

## 1. 添加一个内置服务，总共要做的事

1. 新建 `Core/Services/NSP<名字>Service.h`。
2. 新建 `Core/Services/NSP<名字>Service.m`。
3. 新建 `Preferences/Resources/<名字>.plist` 设置界面。
4. 如需额外共享设置项（per-app 覆盖字段、设备/声音列表等），新建
   `Preferences/Services/NSPSharedSpecifiers+<名字>.m` 自注册 specifier builder。
5. 构建，`Generated/BuiltinServices.generated.h` 会自动更新。

不需要手工改 Makefile 的服务名单；唯一需要手改 Makefile 的是新增
`Preferences/Services/NSPSharedSpecifiers+<名字>.m` 时把它加进 `Pusher_FILES`。

## 2. 核心架构

### 2.1 数据流

```
SpringBoard 收到通知
  → BBServer hook (Tweak.xm)
  → NSPBulletinAdapter：把 BBBulletin 一次性转换成语义无关的值对象 NSPBulletinContext
      （原始字段 + 组合后的 displayTitle/displayMessage + 附件 URL + 图标 provider
        + 该 App 的通知设置）；也是唯一的 SpringBoard 依赖点
  → NSPusher.handleBulletin:
      全局过滤 / 内容防循环（title+subtitle+message 去重，10/25 触发）
      → 对每个已启用服务调用 sendToService:
         服务类 +requestForBulletinContext:config:completion:
         返回/回调 NSPushRequest
      → NSPushRequestSender 发送
```

### 2.2 关键文件

| 文件 | 作用 |
| --- | --- |
| `Core/NSPushService.h/.m` | `NSPPushService` 协议、`NSPushServiceBase` 基类、`NSPushServiceManager` 注册表 |
| `Core/NSPushRequest.h/.m` | 请求模型：`urlString`、`headers`、`infoDict`、`logInfoDict`、`method`、`bodyType`、`resendHandler`、`resendCount`、`failureReason` |
| `Core/NSPushConfig.h/.m` | 读取 prefs 的 `NSPushPrefs` 类（声明在 `NSPushConfig.h`），构建 `NSPushServiceConfig`，调用 `urlForEventName:dbName:serverURL:` 生成 URL 模板 |
| `Core/NSPushConfigModels.m` | `NSPushServiceConfig` / `NSPushConfigSnapshot`，`effectiveConfigForAppID:` 合并 per-app 覆盖 |
| `Core/NSPusher.m` | 分发入口（hook 边界：只在此做一次 BBBulletin → NSPBulletinContext 转换） |
| `Core/NSPushSupport.h/.m` | 管线值对象：`NSPBulletinContext` / `NSPushNotificationSettings` / `NSPDeviceState`，以及图片 helper；不含 SpringBoard 依赖 |
| `Core/NSPBulletinAdapter.h/.m` | **唯一的 SpringBoard 边界**：把 BBBulletin / BBSectionInfo / SBApplicationController / SBIconController / SBLockScreenManager / SBWiFiManager 转换成上面的值对象 |
| `Core/NSPushRequestSender.m` | GET/HEAD query、其他方法 JSON/form、重试、图片缩小重发、按 `logInfoDict` 记日志 |
| `Core/Services/` | 每个服务一个 `NSP<Xxx>Service.h/.m` |
| `Shared/NSPushPrefsStore.h/.m` | 偏好设置读写 |
| `Shared/NSPushLogStore.h/.m` | 日志读写 |
| `Generated/BuiltinServices.generated.h` | 构建期自动生成的服务 import 和名单 |
| `Preferences/Resources/<服务名>.plist` | 服务设置页 |

### 2.3 注册与名单生成

- 每个内置服务在 `+load` 中调用
  `[NSPushServiceManager registerServiceClass:self forName:[self serviceName]];`。
- `NSPushServiceManager` 查不到名字时返回 `NSPCustomService`。
- `scripts/generate_builtin_services.sh` 扫描 `Core/Services/NSP*Service.h`，
  取每个头文件里**第一个** `#define PUSHER_SERVICE_* @"..."` 宏作为服务名，
  生成 `Generated/BuiltinServices.generated.h`。
- 因此服务名宏必须写在头文件最前面；`_URL`、`_APP_ID` 等变体放在它后面即可。

Preferences 侧采用同样的自注册形式：每个服务的共享设置项 builder 放在独立的
`Preferences/Services/NSPSharedSpecifiers+<名字>.m` 里，在 `+load` 中调用
`[NSPushServicePrefsManager registerBuilder:forService:]` 注册自己。
`NSPSharedSpecifiers get:withAppID:isCustomService:` 不再维护按服务的 if/else
分支，而是用 `builderForService:` 查注册表；没注册 builder 的服务（如飞书）
自然不显示额外共享设置项。

### 2.4 配置存储

- 内置服务：`BuiltInServices[服务名] = { ... }`
- 自定义服务：`CustomServices[服务名] = { ... }`
- 全局应用列表：`Global[appList]`、`Global[appListIsBlacklist]`
- 其余全局开关（`Enabled`、`WhenToPush`、`WhatNetwork`、SNS 等）仍在顶层。
- per-app 覆盖：`BuiltInServices[服务名][customApps][appID]` 或
  `CustomServices[服务名][customApps][appID]`。

读写统一走 `NSPushPrefsStore`；日志统一走 `NSPushLogStore`。

### 2.5 服务返回什么

服务不再分别返回 URL / header / body，而是返回一个 `NSPushRequest`：

```objc
[NSPushRequest requestWithURLString:@"..."
                            headers:@{...}
                           infoDict:@{...}]
// 或指定 method
[NSPushRequest requestWithURLString:@"..."
                            headers:@{...}
                           infoDict:@{...}
                             method:@"GET"]
```

服务负责在 `requestForBulletinContext:config:` 里完整设置 `method`（默认
`POST`）、`bodyType`（默认 `json`，可设为 `form`）以及 `logInfoDict`。
`NSPusher` / `NSPushRequestSender` 不重写请求的语义内容（URL、headers、body 字段、
`method`、`bodyType` 均按服务返回的原样发送），但发送器仍会做三个传输层转换：
1. 从 `infoDict` 剔除 `imageShrinkFactor`（内部重试提示，不进真实 body）；
2. 把 `infoDict` 里的 `UIImage` 对象转成 Base64 字符串（因此 `baseInfoDictForBulletinContext:`
   里放图片直接放 `UIImage` 即可，发送前会自动编码）；
3. GET/HEAD 时把整个 `infoDict` 拼进 query string。

### 2.6 上下文（NSPBulletinContext）

`Core/NSPushSupport.h` 里的 `NSPBulletinContext` 是管线的数据模型，由
`NSPBulletinAdapter` 在 hook 边界填充。过滤器、发送器、日志、服务 payload 构造
都只使用它，所以**服务代码不接触（也不需要）`BBBulletin`**：

| 字段 | 含义 | 典型用途 |
| --- | --- | --- |
| `appID` | `bulletin.sectionID`（bundle ID） | data dict / 重试 key / 日志分组 |
| `appName` | 应用显示名（测试推送为 `Settings`） | data dict |
| `bulletinID` | bulletin 唯一 ID | 重试 key / 日志分组 |
| `date` | 通知时间，永不为 nil | data dict 的日期字段、日志时间戳 |
| `isTest` | 是否测试推送 | 跳过 SNS / 设备条件过滤 |
| `title` / `subtitle` / `message` | **原始** bulletin 字段 | `baseInfoDictForBulletinContext:`、飞书 |
| `displayTitle` / `displayMessage` | **组合**字符串：`"AppName: title"`、subtitle+message | Bark / Pushover / Pushbullet / 企业微信 / IFTTT 裁剪格式 |
| `attachmentURL` | 主附件文件 URL；无附件时为 nil | 需要图片的服务 |
| `iconImageProvider` | 懒加载图标 block，返回 `UIImage`，无图标返回 nil | 需要 `icon` 的服务 |
| `notificationSettings` | 该 App 的通知设置快照（原 `BBSectionInfo` 子集） | 仅框架内部（SNS 过滤） |
| `notificationSettingsUnavailableReason` | 上面为 nil 时的原因文案 | 仅框架内部日志 |

`iconImageProvider` 是 block 而不是现成的 `UIImage`：只有部分服务要图标，而解析
图标（SpringBoard 图标生成 + PNG 编码）比较贵，所以按需调用；它可能在内部 hop 到
主线程，从后台队列调用是安全的。

`NSPushNotificationSettings` / `NSPDeviceState` 同样是值对象，分别对应原来 SNS 过滤器
直接读取的 `BBSectionInfo` 字段，以及 `SBLockScreenManager` / `SBWiFiManager` 的锁屏与
WiFi 状态。`NSPushFilter` 现在只依赖这些值对象，是纯函数。

## 3. 最小示例：Bark

### 3.1 头文件

```objc
#import "../NSPushService.h"
#import <Foundation/Foundation.h>

#define PUSHER_SERVICE_BARK @"Bark"
#define PUSHER_SERVICE_BARK_URL @"https://api.day.app/REPLACE_KEY"

@interface NSPBarkService : NSPushServiceBase
@end
```

### 3.2 实现文件

```objc
#import "NSPBarkService.h"
#import "../../helpers.h"
#import "../NSPushConfig.h"
#import "../NSPushSupport.h"

@implementation NSPBarkService

+ (void)load {
  [NSPushServiceManager registerServiceClass:self forName:[self serviceName]];
}

+ (NSString*)serviceName {
  return PUSHER_SERVICE_BARK;
}

+ (NSString*)urlForEventName:(NSString*)eventName
                      dbName:(NSString*)dbName
                   serverURL:(NSString*)serverURL {
  NSString* finalURL = nil;
  if (serverURL && serverURL.length > 0) {
    if ([serverURL hasSuffix:@"/"]) {
      finalURL = [serverURL stringByAppendingString:@"REPLACE_KEY"];
    } else {
      finalURL = [serverURL stringByAppendingFormat:@"/REPLACE_KEY"];
    }
  } else {
    finalURL = PUSHER_SERVICE_BARK_URL;
  }
  return finalURL;
}

+ (NSPushRequest*)requestForBulletinContext:(NSPBulletinContext*)context
                                     config:(NSPushServiceConfig*)config {
  NSDictionary* infoDict = @{
    @"title" : context.displayTitle ?: @"",
    @"body" : context.displayMessage ?: @""
  };
  NSPushRequest* request =
      [NSPushRequest requestWithURLString:[self replacedKeyURLStringForConfig:config]
                                 headers:nil
                                infoDict:infoDict];
  // 日志安全：用 logInfoDictForInfoDict: 生成去除大字段（如 Base64 图片）的日志副本
  request.logInfoDict = [self logInfoDictForInfoDict:infoDict];
  return request;
}

// 精简示例：只处理 serverURL。真实 NSPBarkService 还会在此返回
// level / volume / badge / call / autoCopy / sound / image / group /
// isArchive / ttl / clickURL / action / id / delete 等可选参数的默认值。
+ (NSDictionary*)extraPrefsForName:(NSString*)name
                      servicePrefs:(NSDictionary*)servicePrefs {
  return @{
    @"serverURL" : XStrDefault(servicePrefs[NSPPreferenceServiceServerURLKey],
                               @"https://api.day.app")
  };
}

@end
```

### 3.3 关键点

- `replacedKeyURLStringForConfig:` 是基类 helper：
  用 `config.rawPrefs[@"key"]` 替换 `config.rawPrefs[@"url"]` 中的 `REPLACE_KEY`。
- `urlForEventName:dbName:serverURL:` 在配置加载阶段生成 URL 模板，存到
  `config.rawPrefs[@"url"]`。
- 没有实现异步 `requestForBulletinContext:config:completion:`，基类会自动包一层调用同步版。
- `extraPrefsForName:` 示例为精简版：真实实现还会为 level/volume/badge 等
  14 个 Bark 可选参数返回默认值（空字符串 = 不发送该参数）。

### 3.4 设置界面

`Preferences/Resources/Bark.plist` 的 `service` 字段必须等于 `Bark`，输入框的 `key`
就是 `BuiltInServices[Bark][key]` 的字段名。普通输入框的读写由 `NSPServiceController`
转发到 `NSPSharedSpecifiers`，最终写入嵌套存储。

注意：`Bark.plist` 只声明了 key 和 serverURL 两个输入框（外加 "Optional Parameters"
分组说明文字）；level/volume/badge 等 14 个可选参数输入框**不在 plist 里**，由
`Preferences/Services/NSPSharedSpecifiers+Bark.m` 在 `+load` 自注册的 builder 动态
生成，与 4.4 企业微信的 touser 输入框同一模式。

## 4. 进阶示例：企业微信（异步请求 + 每应用覆盖）

### 4.1 头文件

```objc
#import "../NSPushService.h"
#import <Foundation/Foundation.h>

#define PUSHER_SERVICE_WECHAT @"Wechat"
#define PUSHER_SERVICE_WECHAT_URL                                              \
  @"https://qyapi.weixin.qq.com/cgi-bin/message/send?access_token="            \
  @"REPLACE_DYNAMIC_KEY"

@interface NSPWechatService : NSPushServiceBase
@end
```

### 4.2 服务特有字段

```objc
+ (NSDictionary*)extraPrefsForName:(NSString*)name
                      servicePrefs:(NSDictionary*)servicePrefs {
  return @{
    @"corpid" : XStrDefault(servicePrefs[NSPPreferenceServiceCorpidKey], @""),
    @"corpsecret" :
        XStrDefault(servicePrefs[NSPPreferenceServiceCorpsecretKey], @""),
    @"agentID" : @(NSPushIntegerValue(
        servicePrefs[NSPPreferenceServiceAgentIDKey], 0)),
    @"touser" : XStrDefault(servicePrefs[NSPPreferenceServiceTouserKey], @"")
  };
}

+ (NSDictionary*)extraCustomAppPrefsForName:(NSString*)name
                                   appPrefs:(NSDictionary*)appPrefs {
  return @{@"touser" : XStrDefault(appPrefs[@"touser"], @"")};
}
```

### 4.3 异步请求

企业微信需要先获取 `access_token`，所以覆写异步方法：

```objc
+ (void)requestForBulletinContext:(NSPBulletinContext*)context
                           config:(NSPushServiceConfig*)config
                       completion:(void (^)(NSPushRequest* request))completion {
  // 组装 body：agentid 必须是整数
  NSString* touser = XStrDefault(config.rawPrefs[@"touser"], @"");
  NSInteger agentIDValue = NSPushIntegerValue(config.rawPrefs[@"agentID"], 0);
  NSDictionary* infoDict = @{
    @"touser" : (touser.length != 0) ? touser : @"@all",
    @"msgtype" : @"text",
    @"agentid" : @(agentIDValue),
    @"text" : @{
      @"content" : XStr(@"%@\n%@", context.displayTitle ?: @"", context.displayMessage ?: @"")
    },
    @"safe" : @0
  };

  NSString* corpid = XStrDefault(config.rawPrefs[@"corpid"], @"");
  NSString* corpsecret = XStrDefault(config.rawPrefs[@"corpsecret"], @"");
  if (corpid.length == 0 || corpsecret.length == 0) {
    if (completion) completion(nil);
    return;
  }

  // 先查缓存；缓存 key = corpid|corpsecret
  NSString* cacheKey = [NSString stringWithFormat:@"%@|%@", corpid, corpsecret];
  BOOL cacheHit = NO;
  NSString* cachedToken = cachedWechatTokenForKey(cacheKey, &cacheHit);
  if (cacheHit) {
    if (completion) {
      completion([NSPushRequest
          requestWithURLString:[[PUSHER_SERVICE_WECHAT_URL
              stringByReplacingOccurrencesOfString:@"REPLACE_DYNAMIC_KEY"
                                        withString:cachedToken] copy]
                       headers:nil
                      infoDict:infoDict]);
    }
    return;
  }

  // 请求 gettoken；GET，参数走 query
  NSString* reqUrl = @"https://qyapi.weixin.qq.com/cgi-bin/gettoken";
  NSDictionary* params = @{@"corpid" : corpid, @"corpsecret" : corpsecret};
  NSMutableArray* queryItems = [NSMutableArray array];
  NSCharacterSet* allowed = [NSCharacterSet
      characterSetWithCharactersInString:@"ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghij"
                                         @"klmnopqrstuvwxyz0123456789-._~"];
  for (NSString* key in params) {
    NSString* encoded = [(NSString*)params[key]
        stringByAddingPercentEncodingWithAllowedCharacters:allowed];
    [queryItems addObject:[NSString stringWithFormat:@"%@=%@", key, encoded]];
  }
  reqUrl = [reqUrl stringByAppendingFormat:@"?%@",
                                          [queryItems componentsJoinedByString:@"&"]];
  NSMutableURLRequest* request =
      [NSMutableURLRequest requestWithURL:[NSURL URLWithString:reqUrl]];
  [request setHTTPMethod:@"GET"];
  [request setValue:@"application/json" forHTTPHeaderField:@"Accept"];

  [[[NSURLSession sharedSession]
      dataTaskWithRequest:request
        completionHandler:^(NSData* data, NSURLResponse* response,
                            NSError* error) {
          NSString* token = @"";
          NSInteger expiresIn = 7200;
          if (!error) {
            id jsonResponse =
                [NSJSONSerialization JSONObjectWithData:data options:0 error:nil];
            if ([jsonResponse isKindOfClass:NSDictionary.class] &&
                [jsonResponse[@"errcode"] isEqual:@(0)]) {
              id accessToken = jsonResponse[@"access_token"];
              if ([accessToken isKindOfClass:NSString.class]) {
                token = (NSString*)accessToken;
              }
              id expiresInValue = jsonResponse[@"expires_in"];
              if ([expiresInValue isKindOfClass:NSNumber.class]) {
                expiresIn = [expiresInValue integerValue];
              }
            }
          }
          if (token.length > 0) {
            // 第三参数为服务器返回的 expires_in；缓存内部会留出安全余量
            cacheWechatTokenForKey(cacheKey, token, expiresIn);
          }
          if (completion) {
            if (token.length == 0) {
              completion(nil); // 失败：让上层跳过发送
              return;
            }
            completion([NSPushRequest
                requestWithURLString:[[PUSHER_SERVICE_WECHAT_URL
                    stringByReplacingOccurrencesOfString:@"REPLACE_DYNAMIC_KEY"
                                              withString:token] copy]
                             headers:nil
                            infoDict:infoDict]);
          }
        }] resume];
}
```

token 缓存必须用文件级 static，否则读和写会各持有一份字典，缓存永远不命中。

上面的示例为了简洁省略了 `logInfoDict` 与 `resendHandler` 的挂载；完整实现见
`Core/Services/NSPWechatService.m`（发送前通过 `wechatPushRequestWithToken:` 统一设置）。
真实实现还比示例多做几件事：`expires_in` 同时接受 NSNumber/NSString、对缺失/非数字
`errcode` 有 `respondsToSelector:` 防护、gettoken 请求 15 秒超时、token 缓存带 60 秒
安全余量（按 `expires_in - 60` 缓存）并对过期失效和并发重复获取（single-flight）做了
处理。照抄示例会缺这些健壮性。

`NSPushRequest` 支持 `resendHandler`：每次发送收到响应后，Sender 会回调服务；服务可以检查
响应内容（例如企业微信 `errcode` 40014/42001 表示 access_token 失效），刷新 token 后通过
`completion(newRequest, NO)` 返回新请求，主框架会自动重新发送。`completion(nil, NO)`
继续走默认处理；`completion(nil, YES)` 停止并记为失败。

注意：resend 与普通网络重试共享同一份 per-bulletin 预算（初始 `PUSHER_TRIES - 1`），
重发次数耗尽后按失败处理（此时若 `newRequest.failureReason` 或原请求的
`failureReason` 存在会记入日志），不会无限重发。

### 4.4 每应用覆盖

- 服务类：`extraCustomAppPrefsForName:appPrefs:` 返回 `touser`。
- Preferences：新建 `Preferences/Services/NSPSharedSpecifiers+Wechat.m`，实现 `+wechat:`
  返回 `touser` 输入框的 specifier，并在 `+load` 里把它注册到
  `NSPushServicePrefsManager`（见下方样板）。不需要改任何共享代码。
- plist：`Wechat.plist` 加 `App Customization` 入口。目前 plist 里的 `defaultTouserKey`
  是死配置：`NSPCustomizeAppsController` 只按服务名读取 `defaultDevicesKey` /
  `defaultSoundsKey` / `defaultEventNameKey` / `defaultIncludeIconKey` 等，没有任何
  代码消费 `defaultTouserKey`，新建 Wechat per-app 覆盖不会复制服务级默认值，touser
  默认留空、发送时回退 `@all`。要让 per-app 默认继承服务级 touser，需要给
  `NSPCustomizeAppsController` 补 Wechat 分支（或删掉 plist 里的死键）。
- `touser` 输入框由 `NSPSharedSpecifiers+Wechat.m` 动态生成，不写在 plist 里。

自注册 builder 的最小样板（以 Wechat 为例）：

```objc
// 文件位于 Preferences/Services/，比 Preferences/ 深一层，import 用 ../ 或 ../../
#import "../NSPSharedSpecifiers.h"
#import "../NSPLocalization.h"
#import "../NSPushServicePrefs.h"
#import "../../Generated/BuiltinServices.generated.h"
#import "../../global.h"

@implementation NSPSharedSpecifiers (Wechat)

+ (NSArray*)wechat:(NSString*)appID {
  // 构建 specifier，target 用 NSPSharedSpecifiers.class（setter/getter 在那里）
  ...
}

+ (void)load {
  [NSPushServicePrefsManager registerBuilder:^NSArray*(NSString* appID) {
    return [NSPSharedSpecifiers wechat:appID];
  } forService:PUSHER_SERVICE_WECHAT];
}

@end
```

`appID` 非 nil 表示当前是 per-app 覆盖页；`NSPSharedSpecifiers get:withAppID:isCustomService:`
会在查表后直接调用 `builder(appID)`。新文件记得加进 `Preferences/Makefile` 的 `Pusher_FILES`。

## 5. 协议方法速查表

| 方法 | 是否必须 | 基类默认 | 说明 |
| --- | --- | --- | --- |
| `+serviceName` | 必须 | nil | 注册名，和宏、plist 文件名一致 |
| `+requestForBulletinContext:config:completion:` | 二选一 | 调用同步版 | 异步构建请求；失败回调 nil |
| `+requestForBulletinContext:config:` | 二选一 | 抛异常 | 同步构建 `NSPushRequest` |
| `+extraPrefsForName:servicePrefs:` | 可选 | `@{}` | 服务特有字段默认值 |
| `+extraCustomAppPrefsForName:appPrefs:` | 可选 | `@{}` | per-app 覆盖字段 |
| `+urlForEventName:dbName:serverURL:` | 可选 | `@""` | 生成 URL 模板 |
| `+shouldIncludeIconForConfig:` | 可选 | NO | 是否在共享 data dict 中加图标 |
| `+shouldIncludeImageForConfig:` | 可选 | NO | 是否在共享 data dict 中加图片 |
| `+replacedKeyURLStringForConfig:` | helper | 替换 `REPLACE_KEY` | 用 `key` 替换 URL 模板占位符 |
| `+baseInfoDictForBulletinContext:config:` | helper | 共享 data dict | 生成通用字段 + 可选 icon/image |
| `+logInfoDictForInfoDict:` | helper | 复制并替换大字段 | 生成日志安全的请求体（替换 `logImageDataProperties` 列出的字段） |
| `+logImageDataProperties` | 可选 | `icon`、`image` | 日志中替换为 `PUSHER_LOG_IMAGE_DATA_REPLACEMENT` 的字段名列表；服务按自身 body 布局覆盖（无 Base64 字段的服务返回 `@[]`，如 Bark） |

---

## 6. 注意事项

- `NSPushRequestSender` 支持 GET/HEAD query，其他方法支持 JSON 或 form 表单（`application/x-www-form-urlencoded`）。
- 服务应设置 `logInfoDict`（可用 `logInfoDictForInfoDict:` 生成）；未设置时发送器会回退记录真实请求体。主框架不会重写日志体。
  `logInfoDictForInfoDict:` 默认把 `icon` / `image` 两个字段替换为 `PUSHER_LOG_IMAGE_DATA_REPLACEMENT`；
  若服务的 Base64 图片字段不叫这两个名字（或根本没有 Base64 字段），覆盖 `logImageDataProperties` 返回自己的字段名列表即可。
- `devices` 是字典数组；`sounds` 在 `NSPushConfig` 加载后是已启用声音 ID 的字符串数组。
- 新增服务后记得在 `Preferences/Resources/zh-Hans.lproj/Localizable.strings`
  加显示名。
- 不要直接修改 `Generated/BuiltinServices.generated.h`，它是构建期生成的。
